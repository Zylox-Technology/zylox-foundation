# Operations Principles

## 1. Controlled change

Todo cambio relevante debe ser revisable, trazable y reversible.

## 2. Protect stable branches

Las ramas estables deben estar protegidas.

Ningún cambio crítico debe entrar sin revisión.

## 3. Automate repeatable delivery

Todo proceso repetitivo de build, test y deploy debe tender a automatizarse.

## 4. Quality gates before release

Una release no debe depender solo de confianza subjetiva.

Debe tener criterios explícitos.

## 5. Environments must be intentional

Cada ambiente debe tener propósito, datos permitidos, owners y reglas.

## 6. Operability is part of design

Un sistema no está listo si no puede ser observado, desplegado, diagnosticado y recuperado.

## 7. Incidents create learning

Todo incidente relevante debe generar aprendizaje, no culpables.

## 8. Access must be minimal

Cada persona, herramienta o agente debe tener el mínimo acceso necesario.

## 9. Secrets are never casual

Los secretos no se comparten por chat, documentos sueltos ni repositorios.

## 10. Documentation enables recovery

Cuando algo falla, la documentación operativa reduce tiempo, estrés y riesgo.
