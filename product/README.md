# Product

El módulo Product define cómo Zylox transforma problemas en productos.

Product conecta negocio, usuario, ingeniería y calidad. Su objetivo es evitar construir funcionalidades sin problema claro, sin usuario definido, sin hipótesis validable o sin criterio de éxito.

## Principio rector

> Build the right thing before building the thing right.

Construir lo correcto antes de construirlo correctamente.

## Relación con otros módulos

- `company/`: define cultura, visión y principios.
- `engineering/`: transforma alcance y reglas en solución técnica.
- `quality/`: valida riesgos, criterios de aceptación, evidencia y confianza de release.
- `ai/`: asistirá discovery, síntesis, documentación y análisis, sin reemplazar criterio humano.

## Alcance

Product cubre:

- discovery;
- problem framing;
- usuarios y personas;
- user journeys;
- hipótesis;
- MVP;
- roadmap;
- épicas e historias;
- criterios de aceptación;
- priorización;
- métricas;
- PRD;
- release planning;
- feedback loops;
- colaboración con IA.

## Escenarios cubiertos

Este módulo debe usarse cuando:

- se inicia un producto nuevo;
- se evalúa una idea;
- se define un MVP;
- se baja una necesidad de negocio a backlog;
- se escriben épicas o historias;
- se discute prioridad;
- se define roadmap;
- se preparan criterios de aceptación;
- se conecta discovery con delivery;
- se miden resultados post-release;
- se quiere evitar construir features sin impacto.

## Criterio de cumplimiento

Un proyecto alineado con Product debe poder demostrar:

- problema definido;
- usuario o segmento identificado;
- hipótesis explícitas;
- alcance inicial;
- MVP justificado;
- criterios de aceptación;
- riesgos principales;
- métricas de producto;
- backlog priorizado;
- relación con Engineering y Quality.
