# Code Review

## Objetivo

El review no existe para encontrar culpables.

Existe para proteger el producto.

## Qué revisar

- Correctitud funcional.
- Claridad.
- Testabilidad.
- Seguridad.
- Diseño.
- Acoplamiento.
- Documentación.
- Impacto en arquitectura.
- Riesgos.

## Regla

Si una decisión afecta arquitectura, debe documentarse en ADR o RFC.
