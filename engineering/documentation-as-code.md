# Documentation as Code

## Principio

La documentación es parte del producto.

Debe vivir en el repositorio, versionarse con Git y evolucionar junto al código.

## Qué documentamos

- Decisiones arquitectónicas.
- Procesos.
- Contratos de API.
- Casos de uso.
- Reglas de negocio.
- Estrategias de testing.
- Riesgos.
- Supuestos.
- Limitaciones conocidas.

## Qué no documentamos

- Obviedades del código.
- Comentarios que repiten lo que una función ya expresa.
- Documentos duplicados sin dueño.
- PDFs muertos que nadie actualiza.

## Reglas

- Todo documento debe tener propósito.
- Todo documento debe tener ubicación clara.
- Todo documento importante debe poder revisarse en PR.
- Si una decisión cambia, el documento debe cambiar.
